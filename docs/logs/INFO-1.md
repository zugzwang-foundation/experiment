## Decisions made

- **Ultracode/Workflow-tool: not used**, despite the session default being on. CLAUDE.md §6 defaults it FORBIDDEN for this repo and the kickoff never states PERMITTED; even if it had, the task fails 2 of the 4 required conditions (published PR artifact, ordered proof obligations). Direct execution, explicit subagent calls only.
- **`PriceBar.tsx`'s native `title` kept byte-identical**, `InfoTip` layered beside it — the one wall-driven exception to "remove title everywhere." `market-header.test.tsx` (walled) pins that exact attribute value at two assertions.
- **`InfoTip` does not use `Popover.Trigger`.** Radix's `Popover.Trigger` stamps `type="button"`, `aria-haspopup="dialog"` and `aria-controls` onto whatever it clones onto — invalid and misleading on the ~20 of 29 wired sites that aren't buttons (a `<span>` glyph, a `<th>`, an `<a>`, where `type` means MIME type). Verified against the shipped Radix source, not assumed. Replaced with `Popover.Anchor` (pure position tracking, no semantics) + a hand-driven `open` state merged onto the child via `Slot` — the same prop-merge `Trigger` used internally, without the button baggage.
- **`InfoTip`'s own `id`/`aria-describedby` override was dropped from the Tooltip (hover) branch.** Radix's `TooltipTrigger` already sets `aria-describedby` to its own internal, always-in-sync `VisuallyHidden` copy of the content when open; my own override left the visible content ALSO carrying a description, so an open tooltip described itself twice. Confirmed via the shipped source and a targeted render check.
- **`RulesControl.tsx` reverted off `InfoTip`, kept `title={HEADER_GLOSSARY.rules}`** (native, not `InfoTip`) — measured, not assumed: tapping the button also opens `OnboardingDeck` (a Radix `Dialog`), which `aria-hide`s the rest of the page — including the just-opened `InfoTip` trigger — the instant it mounts. The popover has no window to coexist in; confirmed the gloss text never reaches `document.body`. The modal it opens explains the product far more completely than a one-line gloss would, so nothing is lost for a touch user — they get the deck.
- **`InfoTip` uses a content-hash id (`contentHashId`, exported), not `React.useId()`.** `useId()` prefixes by React root, breaking this repo's "does a 404 degrade to byte-identical markup" idiom across several existing render tests (`market-thumb.test.tsx`, `page-states.test.tsx`) the moment either compared render passed through an `InfoTip`. A deterministic hash of the (small, closed, founder-ratified) `content` string is stable across roots; the accepted cost is that two simultaneously-open `InfoTip`s sharing identical gloss text share one DOM id, harmless here because identical content means identical description regardless of which physical node answers it.
- **Anchor #4 (`GLOSSARY.dharma` on `StatLine.tsx:59`) landed in the header-wiring commit (3), not the profile/discovery commit (5) the brief's slice table assigned it to** — no shippable state existed between wiring `StatLine.tsx`'s two sub-strings (`dharma` + `stakedMarket`, same file, same line region) separately. Doctrine's "slice boundaries may move" rule.
- **The four "Sold" render sites collapse onto one exported `SOLD_LABEL`** (§3.5 of the brief) rather than each typing the literal — so the rendered word and its `GLOSSARY.sold` gloss cannot drift apart at only one of the four.
- **`PositionsTable.tsx:1128`'s "Sold" tag wired, not skipped as NOT NEEDED.** The brief flagged it as possibly RF-13-suppressed dead code; measured instead of assumed — `const sold = sell.soldLotId === tile.key` is a transient "just sold" confirmation flash inside the OPEN tab, a different concept from RF-13's ruling against a *permanent* per-row status tag on top of the Closed-tab split. Reachable; wired.
