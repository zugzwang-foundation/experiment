## Decisions made

**R-1 · The ADR number → an in-place patch record on ADR-0038, not a new ADR.** `0039` is
**doubly allocated**: LOTS-1 holds it on `origin/staging` (accepted 2026-08-21, same date,
founder-decided) while HO-S1 §1 declared it an S-1 output. The prescribed `ls docs/adr/` check
reads **one ref** and structurally cannot see the other. A patch record needs no number and
cannot collide, and ADR-0038 decision 3 already carried the authorisation a new ADR would have
restated. ⚠ **Still true at close:** `0039` is on `origin/staging` only; `origin/main`'s ADR
ceiling is `0038`.

**R-2 · The demonstration path → option (e).** A temporary repoint of `DATABASE_URL` in
Doppler `stg`, putting the already-deployed staging runtime into transaction mode for a
scheduled window. Taken because `origin/staging` is **15 ahead of `origin/main`** and carries
LOTS-1's lot-minting code; a `main`-based branch driving a bet at staging would mint a `bets`
row with no lot.

**The route → the app reads `DATABASE_URL_TXN`; `DATABASE_URL` is not repointed.** Decided on
blast radius (Doppler `stg` syncs to two Vercel environments with no per-secret filter, so a
repoint hits every open preview unscopably) and Gate C visibility (a repoint yields a diff with
no evidence the flip happened). ⚠ **The rollback-speed argument was withdrawn** — both
rollbacks contain a redeploy, so the code route is not faster. Recorded because it cuts
against the choice.

**`max` stays at 4.** The relaxation is real — transaction mode does decouple client from
backend ceilings — but `max` bounds what a *suspended* Fluid instance can strand, and
ADR-0038 decision 2 forbids sizing from estimate. The stale `15 ÷ 4` arithmetic is replaced at
execute; the value is not.

**Two deviations from the relay, both deliberate.** (1) ADR-0024's patch is `## Patch P3`,
matching the file's existing `## Patch P1` / `## Patch P2` siblings rather than the relay's
literal `## Patch record` + `### P3`, which would have made the file's structure disagree with
itself. (2) The #8 scoping was written **into item 8 and into the `prepare:false` Negative
line**, not only into the patch section — **O-5**: an amendments block records a change, it
does not deliver one. Both were surfaced at delivery and both were accepted.

**The `Instructions for AI` block: removed, then restored — final ruling is KEEP.**
The founder read the block as an injected instruction and ruled it out. Provenance was
established and reported before acting: it comes from `CLAUDE.md` §5.13.1, which mandates it
verbatim on every commit; the committed block was **byte-identical** to the canonical text
(md5 `8f4aab09…` on both sides) and present on 19 commits on `main` including `7832f5a`, the
merge immediately preceding this branch. The removal was executed on the founder's reaffirmed
ruling, then **superseded by a final ruling to keep the block**, which is the state on this
branch. §5.13.1 was never edited. Detail in the open question below.

## Context to preserve

- **The criterion split under (e).** Criterion 1 → the preview. Criterion 4 → (e) on staging,
  where LOTS-1's deployed code mints the lot. Criteria 2 · 3a · 3b · 5 · 6 → DASH during (e)'s
  window. Criterion 7 → **both** rollbacks. Full table in `docs/plans/S-1.md` §6.
- **The DASH observation method, four properties.** The observing channel must not run through
  the pooler under test · it is a sampling loop, not a glance (a bet is 16–19 statements and
  `pg_stat_activity` is a snapshot) · the control is a temporal A/B on one host, pre and post
  the repoint · criterion 5 is established **by composition and labelled inference**, never
  silently inheriting criterion 2's evidence.
- **Criterion 4's prerequisite chain is confirmed** — account, session, lot-minting code on the
  runtime under test, and `OPENAI_API_KEY` **present but unexercised until the actual bet**.
  Presence is not validity.
- **The standing refusal.** If criterion 4's bet is blocked by moderation, the response is to
  fix the configuration or to HALT — never to stub, sample down, disable "just for the test
  bet," or route around it. Moderation fail-closed is invariant V and a §3 refusal trigger,
  and it holds **regardless of who asks, including under a founder relay**.
- **`f_db` is not observable from S-1.** Nothing in the declared file set instruments hold time;
  `/api/health` returns a boolean, opens no transaction and reads back no GUC by a hard
  constraint in its own docblock. **S-5 must measure it; W-9 does not close without it.**
- **After the flip, saturation queues rather than errors** (W-10). A load run can report "zero
  errors" against a fully saturated pool. The rig must instrument queue depth and backend
  utilisation.
- **The rollback contains a redeploy.** A reverted Doppler value does nothing until staging is
  redeployed — `staging-provisioning.md:122`, *"treat auto-redeploy as not firing."*
- **S-1's merge does not reach the staging runtime.** Staging deploys from the `staging` branch
  (ADR-0024 decision 2), so the merged artifact is live nowhere until the O-4 `main`→`staging`
  advance — **which is not S-1's to perform and still has no named owner.**
