## Decisions made

1. **Candidate A** — drop the adapter transaction. One line. ADR-0042 ratifies it.
2. **`transaction: true` is a CAPABILITY, not a STATE.** The ADR's real payload: the flag
   only decides what `adapter.transaction` does *when called*, and leaves every path that
   never calls it untouched. Misreading it put this defect on the wrong door for five days.
3. **ASSERT 2's window starts at the first non-empty idle sample** (founder ruling, option
   1). Its first form intersected across *every* sample, so one empty warm-up sample
   collapsed the result to zero — **the post-fix expectation — and it passed on unfixed
   code.** An assertion that passes in both phases for opposite reasons certifies nothing.
4. **ASSERT 1 and ASSERT 2 are `expect.soft`.** With hard `expect` the settle assertion
   throws first and ASSERT 2 is *never evaluated* — which is how it shipped vacuous. Soft
   makes both report in one run. The two inconclusiveness guards stay hard.
5. **The overlap witness is NOT owner-filtered** (founder ruling). It counts any live query
   on the database, so background traffic satisfies it. Changing it would have altered the
   instrument between the pre- and post-fix runs and broken the before/after pair the exit
   criterion rests on. Recorded in the test docblock and NOT ESTABLISHED #8 instead.
6. **Fence by symbol, never by line (O-8).** The ADR first cited the flag by line; **the
   same commit that carries the fix invalidated that citation** by adding comment lines
   above the flag. `:346` → `:342` → `:343`. Eight citation sites converted to symbol form.
7. **The plan was NOT amended** where the cascade diverged from it. A ratified document does
   not get a silent edit; the divergence is written into ADR-0042 and came to Gate C.
8. **Not rebased onto `9d2a920`.** A squash-merge diffs from the merge base anyway.

## Findings affecting other strata

**Not none. Three.**

1. **`S3-SURPRISE-1` -> S-6 (go-live).** `POST /api/auth/email-otp/request-password-reset`
   is unauthenticated and **not covered by our Turnstile gate** — that gate is path-exact
   on `/email-otp/send-verification-otp`. Better Auth's own 3-per-60s default stores its
   counters in **memory**, which on Vercel serverless is per-instance and resets on cold
   start; **`secondaryStorage` is unconfigured** although Upstash is already a dependency.
   Risk: mail-bomb a participant, burn Resend quota, damage sending-domain reputation over
   a 51-day single-domain run. **Cannot yield a session and is not an enumeration oracle.**
   Pre-existing; not introduced by S-3.

2. **`S3-8` -> S-5. Owner named here, because `claude-progress.md` is gitignored.**
   `src/server/identity-pool/consume.ts`'s *Stranded-tuple semantic* block states that
   Better Auth's OAuth flow does not wrap user-create in a transaction. That was **false**,
   and it is the premise under which nesting a second pool checkout looked free — **this
   comment is where the defect came from.** `@security-auditor` found **both** halves
   wrong: it also claims "the user row rolls back", never true in either mode, because
   `createSession` is invoked outside `createOAuthUser`'s transaction. The fence said
   *report, do not fix*; it is warned about in three places a reader reaches first. **S-5
   already owns that file's neighbourhood (`S3-1`, the `max` measurement).**

3. **Implicit OAuth account linking is ON by vendor default, and ADR-0042 is its first
   record.** `@security-auditor` confirmed the gate holds — it enumerated **all seven**
   writers of `users.email_verified` and found none satisfiable by a non-owner — and
   recommends this get **its own ADR** rather than a paragraph inside ADR-0042, since
   ADR-0042's decision body is declared immutable and the record would vanish with any
   supersession. **Do not block this PR on it.** Take the next free ADR number from a live
   `ls docs/adr/` when that task opens.

⚠ Also for S-5, not a register row: the cascade corrects the plan's blast-radius trace.
`sign-up.mjs:141` is **reached-and-throws**, not unreachable — the route is registered
