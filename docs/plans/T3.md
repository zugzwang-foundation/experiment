# HO-T3 Plan — Client-Side Image Downscale Pipeline

**Author:** Dev D  
**Target File:** `src/components/debate/composer/image-attach.ts`  
**Parent:** `HO-FRONT v2.0 §7-T3`, `HO-OVERNIGHT v1.0 §1`  
**Deliverable:** Native browser canvas downscaling before upload

---

## 1. Objective

Downscale eligible user comment images in the browser before requesting upload credentials or uploading bytes, reducing uploaded payload size while strictly preserving transparency, animation, and text legibility, with zero server or database changes.

---

## 2. Format Eligibility & Passthrough Rules

* **Resize-Eligible Formats:** `image/jpeg`, `image/png`, `image/webp`.
* **Passthrough Formats (Untouched):** `image/gif` and `image/avif` completely bypass the canvas downscaling pipeline to protect multi-frame animations from being flattened to a static first frame.

---

## 3. Dimensional Constraints & Scaling Logic

* **Maximum Longest Edge:** `1600px` (`MAX_LONGEST_EDGE_PX = 1600`).
* **Boundary Rules:**
  * If $\max(\text{width}, \text{height}) \le 1600\text{px}$, return original file unmodified (zero re-compression artifacts).
  * If $\max(\text{width}, \text{height}) > 1600\text{px}$, scale proportionally:
    $$\text{scale} = \frac{1600}{\max(\text{width}, \text{height})}$$
    $$\text{targetWidth} = \text{round}(\text{width} \times \text{scale}), \quad \text{targetHeight} = \text{round}(\text{height} \times \text{scale})$$
* **Legibility Floor:** If the scaled shorter edge ($\min(\text{width}, \text{height}) \times \text{scale}$) falls below `MIN_SHORTER_EDGE_PX` (400px), return the original file unmodified to prevent unreadable text glyphs on tall screenshots.

---

## 4. Format-Specific Encodings (Ratified Changes)

1. **PNG Inputs (Screenshots & Diagrams):**
   * Encoded to **`image/webp` at Quality `1` (Lossless)** (`PNG_TO_WEBP_LOSSLESS_QUALITY = 1`).
   * Rationale: PNG uploads on prediction market arguments are predominantly source screenshots and diagrams. Lossless WebP maintains pixel-perfect text clarity without JPEG/lossy blurring while preserving alpha transparency.
2. **WebP Inputs:**
   * Encoded to **`image/webp` at Quality `0.8`**.
3. **JPEG Inputs:**
   * Encoded to **`image/jpeg` at Quality `0.8`** on an explicit `#ffffff` white ground fill (to prevent transparent edge pixels from flattening to black).

---

## 5. Memory & Crash Safety (The Guards)

1. **40-Megapixel Guard (`MAX_DECODE_PIXELS = 40_000_000`):**
   * If $\text{width} \times \text{height} > 40\text{MP}$, skip canvas allocation and return original file.
   * *Docblock Note:* Caps the canvas surface allocation (~10 MB) to prevent browser memory spikes, noting that source bitmap is resident in memory after decode (~160 MB RGBA at threshold).
2. **Timeout Race Guard (`DOWNSCALE_TIMEOUT_MS = 5000ms`):**
   * Wraps the downscale attempt in a 5000ms `Promise.race`. If decoding hangs on a decompression bomb, it safely falls back to the original file rather than leaving the composer permanently stuck in an attaching state.
3. **Byte-Growth Guard:**
   * If `resizedBlob.size >= originalFile.size`, discard the compressed blob and upload the original file.
4. **Zero-Size Guard:**
   * Rejects empty 0-byte encoder outputs.

---

## 6. Browser Compatibility & Fallback

* Per the W3C Canvas standard, if a browser does not support WebP canvas encoding, `toBlob` silently returns `image/png`.
* The pipeline dynamically reads the returned blob's actual MIME type and size, ensuring valid signing parameters and transparency preservation.

---

## 7. Invariants Satisfied

* Downscale happens **before** upload, never after.
* One stored object, one set of bytes across upload, moderation, and rendering.
* **No second image variant**, unconditionally.
* Signed `contentType` and `byteSize` sent to `/api/uploads/sign` match the post-encode upload blob.
* **8 MiB server-side byte cap** remains strictly enforced.
* **No new headers** on the signed PUT request.
* Zero new npm dependencies (strictly native Web APIs).
