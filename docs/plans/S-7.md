## 1 · DC — reclassified LOW/latent, recorded not demonstrated

**⚠ Amended post-execute — see ADR-0044, the authoritative record.** Everything below this note reflects the plan as it stood before code review and security audit. Security audit found the reachability proof below (and R-D, which it depends on) was scoped to a single request and missed a narrow, non-attacker-inducible cross-request bridge; DC-a was reinstated at `case "hit"` to defend it, and `I-IDEM-NOMASK-001`'s scope claim was corrected to match what it actually proves. This section is left as-written rather than rewritten, matching this project's own convention of amending forward rather than editing history — read ADR-0044 for the current, correct account.

Per addendum §2/§4.1: not reachable under current code or configuration.
`precommitModerate`'s reservation `DEL` is a bare `finally` (runs on every
throw, not just the happy path — addendum R-B), independently closing the
same window my own P-0 trace closed via the TTL-nesting argument
(idem sentinel TTL 30s strictly outlives the mod-reserve TTL 10s, and the
mod-reserve key `{U,M,K}` is a strict superset of the idem key `{U,K}`,
so no second request can ever observe a stale reservation without first
colliding on the coarser, longer-lived idem gate). Addendum R-D
generalizes further: enumerated exhaustively, every cached non-2xx
arises either before `runBetTransaction` opens or after it rolls back —
never after it commits.

**D-3 is not built** (fabricating the precondition by writing Redis
directly is exactly what V-1 forbids). Record in ADR-0044: *"DC's
reachability chain does not close. `precommitModerate`'s DEL is a bare
`finally`; no post-commit error can produce a cached non-2xx; every
cached non-2xx corresponds to a transaction that did not commit."*

**Replacement — the new invariant test.** Assert a cached non-2xx never
coexists with a committed transaction: parameterize over the reachable
cached-error classes (429 rate-limit, 409 durable-mismatch, the 4xx
validation/floor/comment/reply/image family, 409 `ModerationInFlightError`,
409 23505-mismatch), and for each, assert `bet_receipts` holds zero rows
for that idempotency key afterward. Suggested id `I-IDEM-NOMASK-001`
(confirmed against the live `tests/invariants/` register at Phase 2
start — no existing file uses that name).

## 2 · G2 — Design B (unchanged, three reads, zero migration)

Both G2 and the (now-dropped) DC-a would have landed at the same repair
site, `case "hit"` in `runBetEndpoint` (`src/server/bets/endpoint.ts:243-249`).

1. `cache.ts:95` — `getRedisKey("idem", key)` →
   `getRedisKey("idem", userId, key)`. Mirrors `precommit.ts:79-84`'s
   `getRedisKey(RESERVATION_KEY_BASE, userId, marketId, idempotencyKey)`.
   `idempotencyLookupOrReserve`'s signature (`cache.ts:91-94`) gains
   `userId`; its one caller (`endpoint.ts:242`) already has it in scope
   from step 1 (`endpoint.ts:172`).
2. `loadDurableReplay` (`replay.ts:72-99`) gains `userId` in `args` and
   in the `WHERE`. Both call sites already hold it: the pre-check
   (`endpoint.ts:301-304`) has `ctx.userId`; the route's post-tx 23505
   catch (`place/route.ts:215-218`, mirrored in `sell/route.ts`) has it
   via the same `ctx`.
3. The 23505 catch arm (`place/route.ts:213-236`, mirrored in
   `sell/route.ts`) learns a third outcome: if
   `isDurableIdempotencyConflict(err)` is true but the (now user-scoped)
   `loadDurableReplay` returns nothing, emit
   `409 error_idempotency_key_reused` with `noCache: true` (matching the
   existing mismatch-branch shape) instead of rethrowing into an
   uncached 500. This returns through the inner-result channel, which
   already honours `noCache` — this is why deferring DC-b (below) is
   safe.

Two Postgres uniques stay untouched (Design A rejected for this
stratum, recorded in ADR-0044 as the testnet successor). Fence 5.1 (no
rename, no index touch) applies untouched.

**DC-b — deferred**, correct reason per addendum §4.3: the thrown
channel structurally has no `noCache` escape (unlike the inner-result
channel), so any *future* transient 4xx added to the thrown path would
inherit the defect silently. Deferred because nothing reaches it today,
not because `ModerationInFlightError` specifically cannot fire.

**D-4 / D-5 controls (mandatory):** D-4 — same user replaying the same
key still gets the original 200 byte-for-byte, forced on all three
arms. D-5 — rescoped per addendum §5: after the key-shape change, a
terminal 4xx and a 429 for user U under key K must still replay from
cache for U (guards G2, not DC-a, which no longer exists).
